## 软件项目（software）

- 适用时运行测试、lint、类型检查和构建命令。
- 关注回归风险和依赖变化。
- 检查兼容性、临时代码和无必要托底逻辑。
- 保持文档和实际行为同步。

## 前端与视觉验收

- 每个页面在 1440、1024、768、390 px 检查模块顺序、容器、字号、行高、间距、图片裁切、卡片列数、按钮和导航行为。
- 差异分为严重、明显、细节；用户确认前必须修正严重和明显差异。
- 检查键盘导航、焦点、语义、对比度、减少动效、移动端触控区和阿拉伯语 RTL。
- 视觉对照只验证可授权重建的结构和模式，不以复制对方资产为验收方式。

## CMS 与 API 验收

- CPT、分类、字段、关联、发布状态、SEO 和媒体数据必须有可版本化契约。
- 校验 API 鉴权、权限、输入清理、输出转义、错误状态、预览隔离和缓存失效。
- 不直接修改 WordPress 核心；自有插件必须可独立启用、停用、导出配置和回滚。
- 文件上传如进入范围，必须验证扩展名与 MIME、容量、权限、病毒扫描、存储隔离和过期删除。

## 多语言与 SEO 验收

- 校验九种语言的 URL、当前页对应切换、自引 canonical、已发布译文 hreflang 闭包和 `x-default`。
- 未发布或未审核译文不得被索引，也不得出现在语言切换、Sitemap 或 hreflang 中。
- 每个模板检查 Title、Description、H1/H2/H3、Breadcrumb、OG/Twitter、Schema、Alt、Sitemap、robots 和 404。
- 长英文/德文、CJK、印地语和 RTL 内容不得破坏布局或交互。

## 性能和安全底线

- 检查 Core Web Vitals、首屏资源、图片/字体、缓存、按页加载和第三方脚本。
- 开发、预发布和生产必须隔离；预发布必须 `noindex`。
- 每个版本变更在用户验收前必须有构建/测试、实际症状验证、对抗审查和文档影响证据。
