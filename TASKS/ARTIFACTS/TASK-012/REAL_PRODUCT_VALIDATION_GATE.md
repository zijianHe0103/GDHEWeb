## 4.3 已确认的产品页面身份

| 产品或配件类型 | 公开页面身份 | 规格/关系 |
|---|---|---|
| 同款、同型号、出厂配套的电机 + 遥控器 | 一个组合产品页面 | 不拆成两个公开页面；电机和遥控器分别保留独立 Article Number，不创建组合 Article Number |

### 电机与遥控器的部件身份

- 同款、同型号且出厂配套的电机和遥控器共用一个公开页面；
- 电机和遥控器分别保留自己的全公司唯一 Article Number；
- 不为共用页面额外创建组合 Article Number；
- 电机和遥控器是两个独立 RFQ 行项目；客户可只选择电机、只选择遥控器或同时选择两者；
- 两个行项目分别填写数量，数量可以不同。
| 一种类型的布带 | 一个独立类型详情页 | 页面下按颜色、宽度、钉子种类、钉子间距展示实际存在的规格 |
| transparent tape | 与普通布带分开的独立类型详情页 | 作为另一种产品类型，不与普通布带合并 |
| 用户所称“线珠”大类 | 独立类型详情页 | 颜色和具体珠型决定型号；珠距和卷长为规格；正式英文名待资料确认 |
| 轨道封口、走珠、顶码、墙码 | 无独立详情页 | 只作为主产品的相关配件；仍可按 Article Number 独立加入 quotation request |

### 统一配件角色与配件类别

- 产品领域只保留一个“配件”业务角色，不区分“备件”或“套装成员”；
- 配件使用可筛选的“配件类别”组织；
- 当前类别示例包括顶码、墙码、走珠、封口、布带和线珠；
- 配件类别只负责组织、筛选和发现，不决定公开页面身份；
- 因此布带、线珠等配件类别可以有独立类型详情页，而顶码、墙码、走珠、封口等类别仍可只在相关配件区域出现；
- 用户确认“强码”是“墙码”的笔误；系统只保留“墙码”规范类别，不创建“强码”类别。
- 配件与配件类别是多对一关系：每个具体配件必须且只能属于一个配件类别，同一 Article Number 不得同时进入多个类别；一个类别可以包含多个配件。

### 布带当前已知规格轴

- 颜色：黑色、白色；
- 宽度：30mm、45mm、60mm；
- 钉子种类：不锈钢钉、铝钉；
- 钉子间距：125mm、145mm、165mm、170mm 以及更多真实值；
- 长度：30m、40m、50m、60m 等真实值。

布带型号与规格层级已确认：型号由颜色和钉子材质共同决定；同一型号下，宽度、钉距和长度不同会产生独立 Article Number。宽度和钉距使用毫米（mm），长度使用米（m）。上述属性并非所有组合当前都有产品记录；只有飞书产品表中真实存在并具有 Article Number、且满足未来发布规则的组合，才能成为公开可选规格，不得按笛卡尔积自动生成记录。

### 其他配件的型号边界

- 配件不要求每一个具体 Article Number 都拥有独立型号；
- 除布带和线珠外，封口、顶码、吊码、走珠等其他配件通常同时具有型号和独立 Article Number；
- “通常”表示可能存在真实例外，因此型号不能在所有配件上设为无条件必填；例外范围必须通过代表产品资料确认。

### 线珠当前型号与规格结构

- 型号由颜色和具体珠型共同决定；
- 尚飞大方珠系列：单扣尚飞大方珠、双扣尚飞大方珠、大圆扣尚飞大方珠；
- 用户所称佳丽斯中方珠/珠系列：单扣佳丽斯中方珠、双扣佳丽斯中方珠、小圆扣佳丽斯珠；
- 常见珠距：6cm、6.6cm、7cm、8cm、10.2cm；
- 10.2cm 一般用于双扣，但当前只作为常见关系记录，不建立“非双扣禁止 10.2cm”的排他校验；
- 常见卷长：40m、50m、60m 等；
- 不同珠距或不同卷长均产生独立 Article Number，但都不改变型号。

## 4.2 已确认的转化边界

- 主要访客和交易模式是 B2B。
- 网站的核心转化终点是提交 quotation request，而不是创建已确认订单或完成付款。
- 主产品和可独立询价配件都可以进入报价请求。
- 报价请求必须保留用户选择的型号、具体规格和 Article Number；其他必填选项后续逐项确认。
- 当前不规划商品价格结算、购物车 checkout、支付网关或面向消费者的即时订单流程。
- 英语站正常在售产品的统一主询价按钮文案为 `Request a Quote`；不混用 `Ask for Quotation` 或 `Get a Quote`。停产产品继续使用 `Contact Us for Replacement`。
- quotation request 最终在飞书多维表格新增记录，由业务员在飞书完成报价；网站提交成功不等于订单成立或报价已经完成。

## 4.4 飞书与 WordPress 权威边界

已确认事实：

- 飞书多维表格中已经储存部分现有产品；
- 网站未来需要从飞书导入或取得这些产品数据；
- 布带等页面只公开飞书中真实存在的规格记录，不自动创建理论组合；
- 客户提交 quotation request 后，需要在飞书新增记录；
- 业务员在飞书中完成后续报价。

已确认方案 A：

- 飞书持续作为型号、Article Number、规格和可用状态的结构化产品主数据权威；
- WordPress `wp-admin` 持续作为营销文案、SEO、公开媒体和页面编排的内容管理权威；
- 这一区分不取消 `wp-admin` 的内容后台地位，但结构化产品主数据不能在两边同时编辑；
- 产品主数据只允许从飞书单向流向网站侧，不默认实施双向同步；
- quotation request 从网站写入飞书是独立的业务写入方向，不构成产品主数据反向同步。

已确认编辑行为：

- 型号、Article Number、规格和可用状态在 `wp-admin` 中可查看但只读；
- 这些字段只能在飞书修改；
- 产品介绍、SEO、公开图片和页面模块继续在 `wp-admin` 编辑；
- 飞书修改后通过单向同步更新 WordPress/网站侧只读数据。

已确认敏感数据隔离：

- 成本、采购价、内部销售底价、利润/利润率、供应商信息、库存数据和客户专属报价只保存在飞书多维表格；
- 内部备注和业务审核记录同样只保存在飞书；WordPress 只保留自身公开内容的编辑修订历史；
- 这些字段不是“同步到网站后隐藏”，而是不得进入 WordPress 产品镜像、GDHE REST API、Next.js、公开缓存或应用日志；
- 后续字段映射采用公开字段白名单；未在白名单中的飞书字段默认不读取、不传输、不落库；
- 真实 Base 尚未读取或修改，当前记录的是业务隔离规则，不代表同步代码已经实现。

已确认第一批公开字段白名单：

- 产品名称、型号和 Article Number；
- 飞书中真实存在的可选规格、尺寸、颜色和表面处理；
- 技术参数、安装方式和兼容关系；
- 在售/停产状态；
- 产品图片和当前有效资料。

“进入白名单”只表示字段允许公开，不表示任意飞书记录会自动发布。记录仍须满足显式网站发布资格、Article Number 和数据校验规则，并经过 WordPress 对应的发布状态门。

### 已确认的包装来源标签与客户含义

本节证据来自用户提供的飞书选项截图和逐项业务说明，不是对真实 Base 表、字段类型或产品记录的在线读取。

| 飞书来源标签 | 已确认业务含义 | 官网表达边界 |
|---|---|---|
| 常规 | 一层防撞膜，外层再加尼龙带，减少运输摩擦 | 作为基础保护包装说明 |
| 纸盒 | 在泡沫膜外增加纸盒，以纸盒替代最外层膜 | 作为增强型外包装说明 |
| 打字 | 按客户需求在轨道上印刷客户自己的 Logo | 英文不得直译“打字”；最终客户标签待英语文案任务冻结 |
| 套袋 | 每支轨道单独套 PP 膜并经过热塑机保护；常规状态是不套袋 | 表达为单支保护选项 |
| 大收缩膜 | 每扎轨道不采用常规“泡沫棉 + 尼龙带”，改用大塑封膜并热塑收缩 | 表达为整扎收缩包装 |
| 对扣 | 两根轨道两两对扣以节省装柜空间；保护程度低于单支套袋 | 同时说明装柜效率和保护取舍 |

当前六项应拆为三个客户选择维度：

1. `基础包装`：必选；常规包装、纸盒包装、大收缩膜包装三选一；
2. `Logo 印刷`：可选独立开关，可与任一合法基础包装和保护/排列状态组合；
3. `保护/排列方式`：可选；可以不选，选择时单支套袋与对扣二选一。

用户明确确认以下兼容组合：

- 常规包装 + Logo 印刷 + 单支套袋；
- 常规包装 + Logo 印刷 + 对扣；
- 纸盒包装 + Logo 印刷 + 单支套袋；
- 纸盒包装 + Logo 印刷 + 对扣；
- 大收缩膜包装 + Logo 印刷 + 单支套袋；
- 大收缩膜包装 + Logo 印刷 + 对扣。

上述规则已经足以冻结未来轨道类 RFQ 的字段基数和互斥校验，但尚未确认真实记录分配；当前任务仍不授权实现 RFQ 表单或修改 WordPress Schema。

### 布带和线珠的独立包装合同

- 布带和用户所称“线珠”不适用上述轨道包装合同；
- 两类产品的官网常规包装均为纸箱包装，作为公开默认包装说明；
- 特殊“组合包装”在业务上存在，但不在官网展示，也不提供给客户作为 RFQ 自助选项；只由业务员针对本身已有该需求的客户单独提供；
- “常规包装”是类别相关术语：轨道类表示防撞膜加尼龙带，布带/线珠类表示纸箱。后续 WordPress 配置、API 合同和 RFQ 规则必须使用类别限定的身份，禁止用一个全局“常规”值承载两种含义；
- 封口、走珠、顶码、墙码等小型相关配件采用固定纸箱包装；官网不提供包装选择。

### 电机和遥控器的固定包装合同

- 同款、同型号且出厂配套的电机和遥控器采用固定纸箱包装；
- 官网可以展示纸箱包装说明，但不向客户提供任何包装选择；
- API 和 RFQ 不应为这类产品输出包装选项集合；
- 该固定事实不复用轨道类三维选择合同，也不复用布带/线珠的公开默认加线下特殊服务合同。

### 小型相关配件的固定包装合同

- 适用于封口、走珠、顶码、墙码等不单独建立公开详情页的小型相关配件；
- 固定使用纸箱包装；
- 官网不提供包装选项，API 和 RFQ 不输出包装选择集合；
- 该固定事实不复用轨道、布带/线珠或电机/遥控器的包装合同。

已确认产品读取拓扑：

1. 飞书产品主数据经受控同步进入 WordPress 只读镜像；
2. WordPress 将主数据镜像与 `wp-admin` 维护的营销内容组合，经 GDHE REST API 输出；
3. Next.js 只消费 GDHE REST API，不在公开页面请求中直接读取飞书；
4. 同步校验失败时不得用无效新数据替换最后一次成功的公开数据；
5. quotation request 使用独立受控写入通道新增飞书询价记录，不修改产品主数据。

已确认同步资格门：

- 飞书必须具有显式的网站发布资格字段；
- 只有被业务方标记为“允许发布”的记录才可能进入同步范围；
- 记录还必须具有有效且全公司唯一的 Article Number，并对应真实存在的规格；
- 未标记、状态不明确或数据校验失败的记录默认不进入同步范围；
- 当前确认的是业务规则，不代表已经在真实 Base 中创建字段。

已确认发布生命周期：

- 首次获得同步资格的产品只创建 WordPress 草稿；
- 编辑人员完善 WordPress 管理的文案、SEO、图片和页面模块后手动发布；
- 已发布产品的普通飞书主数据变更通过校验后自动更新只读镜像，并保持原公开状态；
- Article Number、型号归属、产品记录删除和撤销网站发布资格属于重大变更，进入例外审核，不自动覆盖或下线；
- 同步不得覆盖 WordPress 管理的营销内容；
- 任何校验失败都保留最后一次成功公开数据并产生可追踪错误。

已确认停产页面策略：

- 停产产品保留原 URL 和公开页面，不直接删除；
- 页面显著标记 `Discontinued`；
- 存在替代型号时展示替代产品链接；
- 常规询价 CTA 改为 `Contact Us for Replacement`；
- 该策略保留历史客户查询和 SEO 入口，不代表停产产品仍可按原型号供货；
- 替代/升级关系、停产生效日期和无替代型号时的支持内容仍需真实样本验证。

已确认下载资料生命周期：

- WordPress、飞书网站镜像和公开媒体只保存当前有效文件；
- 当前文件记录类型、版本号、语言和生效日期；
- 同一当前文件可以关联多个产品；
- 新版本生效时，网站关系切换到新文件并移除旧文件；
- 失效旧版本由极空间独立归档，不在网站内容层重复保存；
- 极空间历史库不进入公开 API 或网站同步路径；
- 当前只确认边界，未连接极空间，也未移动或删除任何文件。

仍待确认：

3. 停产、替代、升级型号的真实关系字段、生效日期和无替代型号内容；
