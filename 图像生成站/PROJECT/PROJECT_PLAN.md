## 2. 项目摘要

项目暂定名称：

> **GDHE Curtain Track Visualizer / GDHE 窗帘轨道场景可视化工具**

项目目标是提供一个由 GDHE 授权经销商在桌面网页中使用的销售展示工具：

1. 经销商在浏览器中选择客户提供的窗户实景照片；
2. 手动标记窗户、窗帘覆盖区域和轨道安装线；
3. 在照片上指定一段已知距离并填写实际尺寸；
4. 选择 GDHE 轨道、电机、安装环境和静态窗帘示意模板；
5. 系统依据用户标定和真实产品数据，按已校准展示比例合成轨道与电机；
6. 浏览器本地生成带固定 GDHE 品牌的静态展示图并下载。

系统的核心不是“生成一间新房间”，而是：

> **保留客户原照片，用确定性几何、真实五金尺寸和固定视觉素材完成静态场景合成。**

## 3. 已确认的核心决定

以下决定属于 `CONFIRMED`：

1. 不使用图片大模型。
2. 不训练模型，不建设 AI 生成服务、任务队列或自动重试系统。
3. 不按生成次数计费，不建设额度或会员套餐。
4. 客户照片由应用在浏览器本地读取、编辑和导出；应用不向 GDHE、WordPress、对象存储或第三方服务上传或持久化照片。
5. 不保存项目、不提供历史记录、不提供云端分享链接。
6. 不建设经销商项目管理中心。
7. 不提供经销商自定义 Logo 或白标；界面与导出统一使用 GDHE 品牌。
8. 首版需要申请权限才能访问。
9. 必须预留 `approval_required`、`public`、`disabled` 三种访问模式，使未来开放无需重写编辑器。
10. 窗帘是辅助说明轨道应用效果的静态视觉模板，不是 GDHE 销售的面料 SKU。
11. 不做窗帘开合动画、布料物理模拟、真实波峰数量、走珠数量或用布量计算。
12. 轨道和电机属于真实产品展示元素，尺寸、纵横比和锚点不能由用户自由破坏。
13. 用户通过照片中的参考线和实际尺寸建立展示比例，不依赖图片大模型。
14. 首版主要面向桌面网页，不做移动端复杂编辑。
15. 嵌入式电动轨道的电机必须显示，且用户不能隐藏。

## 4. 产品定位

### 4.1 它是什么

- 面向 B2B 经销商的销售辅助工具；
- 静态、确定性的二维/2.5D 场景合成工具；
- 真实轨道和电机的视觉比例展示工具；
- 用固定中性窗帘表达不同轨道应用效果的工具；
- 统一输出 GDHE 品牌材料的工具。

### 4.2 它不是什么

- 不是 AI 室内设计或图片生成平台；
- 不是施工测量工具；
- 不是轨道长度自动测量工具；
- 不是安装位置自动识别工具；
- 不是 BOM、报价或下单系统；
- 不是面料选购系统；
- 不是布料物理仿真系统；
- 不是 AR 或 3D 房间重建工具；
- 不是经销商 CRM、项目中心或资产库。

### 4.3 对“真实比例”的准确表述

本项目统一使用：

> **已校准展示比例 / calibrated visual scale**

不得使用“自动测量”“施工级真实比例”或“精确还原”等表述。

用户输入的参考尺寸只能帮助系统将同一平面、相近位置和相近方向上的产品尺寸映射为合理视觉比例。以下内容仍然是近似：

- 天花板平面与墙面平面之间的转换；
- 墙码向房间方向伸出的深度；
- 电机前后厚度；
- 双轨前后间距；
- 严重侧拍、仰拍或广角畸变中的空间关系。

所有正式导出必须包含：

> Visualization only. Final dimensions and installation conditions must be verified on site before ordering.

最终英文文案由品牌和业务人员确认后冻结。

## 5. 目标用户与使用场景

### 5.1 首要用户

- 已获 GDHE 授权的经销商；
- 需要向客户解释不同轨道安装效果的销售人员；
- 需要在客户实景图上快速制作静态展示图的业务人员。

### 5.2 首版核心场景

1. 客户把窗户照片发给经销商；
2. 经销商在 GDHE 网站打开工具；
3. 经销商标记位置并选择产品组合；
4. 经销商下载带 GDHE 品牌的效果图；
5. 经销商将效果图用于讲解产品和安装场景。

### 5.3 非首版用户场景

- 终端消费者自助注册和长期管理项目；
- 安装师傅据图施工；
- 经销商上传自己的品牌；
- 多人协同编辑；
- 通过公开链接继续编辑；
- 从效果图直接产生正式报价或订单。

## 7. 端到端用户流程

### 步骤 1：访问工具

系统读取服务端访问模式：

- `approval_required`：未授权用户进入申请页；授权用户进入工具；
- `public`：任何访客可直接进入工具；
- `disabled`：工具关闭，不加载编辑器。

### 步骤 2：本地选择照片

页面明确说明：

- 使用普通 1× 镜头；
- 尽量正对窗户；
- 窗户位于画面中央；
- 拍到窗户顶部和安装区域；
- 落地帘要拍到地面；
- 尽量减少大面积家具遮挡；
- 当前应用不会主动上传或保存照片。

首版建议接收 JPG、PNG 和 WebP。HEIC、异常编码、超大图和色彩空间兼容性由 PoC 决定；未通过验证的格式应明确拒绝，而不是静默失败。

### 步骤 3：标记窗户

用户设置：

- `P1` 左上；
- `P2` 右上；
- `P3` 右下；
- `P4` 左下。

形成 `windowQuad`，用于表达照片中的窗户位置和局部透视。

### 步骤 4：标记窗帘覆盖区域

用户单独设置 `curtainQuad`。它可以：

- 只覆盖窗框；
- 左右超出窗框；
- 从天花板或窗帘盒下沿延伸到地面；
- 覆盖整面墙的目标区域。

`windowQuad` 和 `curtainQuad` 必须是两个独立对象。

### 步骤 5：设置尺寸参考线

用户选择 `calibrationLine` 的两个端点并填写已知实际距离。

首选参考类型：

1. 窗框实际宽度；
2. 预计轨道实际长度；
3. 窗框实际高度；
4. 高级模式下的自定义已知距离。

系统不得从照片自行声称测得真实距离。

### 步骤 6：设置轨道安装线

用户设置 `trackLine`：

- 起点；
- 终点；
- 上下位置；
- 左右延伸范围。

轨道长度以用户定义和校准关系为基础；轨道厚度、端盖比例和电机尺寸来自已验证产品数据。

### 步骤 7：选择安装环境与产品

选择顺序：

```text
安装环境
  → 驱动方式
  → 单轨/双轨
  → 兼容轨道
  → 兼容电机
  → 帘型示意
  → 静态模板
  → 基础颜色
```

缺少真实兼容数据或视觉资产的组合必须禁用，并显示缺失原因。不得用“相似素材”静默兜底。

### 步骤 8：检查与微调

用户可以调整：

- `curtainQuad`；
- `trackLine`；
- 电机左/右侧；
- 窗帘模板；
- 基础颜色；
- 视觉透明度和有限的亮度预设。

用户不能自由修改：

- 轨道真实厚度；
- 电机纵横比；
- 电机真实尺寸；
- 电机和轨道锚点；
- 强制显示规则。

### 步骤 9：本地导出

浏览器使用原图坐标重新绘制：

1. 客户原图；
2. 静态窗帘；
3. 嵌入式槽口或安装结构；
4. 轨道；
5. 电机；
6. GDHE Logo、网址和免责声明。

导出结果直接下载到用户设备，不先上传服务器。

## 8. 安装场景规则

以下是产品层的展示规则。具体轨道/电机型号仍须经过真实产品验证。

| 安装环境 | 驱动 | 轨道 | 支架 | 电机 | 校准要求 |
|---|---|---|---|---|---|
| 窗帘盒 | 手动 | 场景图隐藏 | 隐藏 | 无 | 可选；正式比例说明仍需明确 |
| 窗帘盒 | 电动 | 场景图隐藏 | 隐藏 | 可隐藏于盒内 | 可选；产品卡单独展示电机 |
| 嵌入式 | 手动 | 显示细槽或嵌入式轨 | 隐藏 | 无 | 建议必填 |
| 嵌入式 | 电动 | 显示细槽或嵌入式轨 | 隐藏 | **强制显示并锁定** | **必填** |
| 明装顶装 | 手动 | 显示 | 显示或简化顶装件 | 无 | 必填 |
| 明装顶装 | 电动 | 显示 | 显示或简化顶装件 | 显示 | 必填 |
| 明装墙装 | 手动 | 显示 | 显示墙码 | 无 | 必填 |
| 明装墙装 | 电动 | 显示 | 显示墙码 | 显示 | 必填 |

### 8.1 嵌入式电动强制规则

`CONFIRMED`：

```text
installation = recessed
drive = motorized
motorVisible = true
motorVisibilityLocked = true
calibrationRequired = true
```

该规则不能被“隐藏五金”通用逻辑覆盖。

### 8.2 窗帘盒电动规则

`CONFIRMED`：

```text
installation = curtain_box
drive = motorized
trackVisible = false
motorVisible = false in scene
```

产品信息卡仍可显示真实轨道和电机，避免场景图隐藏导致产品身份不清楚。

## 9. 核心领域对象与术语

| 对象 | 含义 | 是否持久化 |
|---|---|---|
| `SourceImage` | 用户在当前页面选择的客户照片 | 否 |
| `windowQuad` | 实际窗框的四点区域 | 否 |
| `curtainQuad` | 静态窗帘视觉覆盖区域 | 否 |
| `calibrationLine` | 用户给出真实长度的参考线 | 否 |
| `trackLine` | 轨道安装起点与终点 | 否 |
| `SceneState` | 当前编辑器的几何、选择和显示状态 | 否，仅内存 |
| `VisualSystem` | 安装环境、驱动和显示规则的组合 | 是，服务端配置 |
| `TrackVisual` | 轨道视觉资产及真实尺寸元数据 | 是 |
| `MotorVisual` | 电机视觉资产、视角、真实尺寸和锚点 | 是 |

| `AssetManifest` | 受版本控制的视觉资产清单 | 是 |
| `AccessPolicy` | 三种访问模式及授权规则 | 是 |

统一术语：

- 罗马杆：轨道/杆件系统；
- 罗马帘：帘体产品；
- 两者不得混用；
- “Wave 倍数”只表示静态视觉模板；
- “已校准展示比例”不等于自动测量。

### 10.1 不存在的服务

首版架构中没有：

- 图片上传 API；
- 客户图片对象存储；
- 场景数据库；
- 图片渲染 Worker 服务；
- AI 服务；
- Redis 或任务队列；
- 额度账本；
- 支付服务；
- 云端分享服务。

### 10.2 现有架构接入原则

上级独立站现有前端只能消费受控 GDHE DTO，不能让可视化编辑器直接读取 WordPress 原始字段。

后续接入应继续采用：

```text
WordPress GDHE REST
  → server-only Transport
  → Runtime Validator
  → Adapter
  → VisualizerCatalogDTO
  → Server Component
  → Client Editor
```

## 11. 浏览器本地照片处理边界

### 11.1 应用承诺

应用必须做到：

- 从用户选择的 `File`/`Blob` 在浏览器端解码；
- 不通过 `FormData`、JSON、Base64、日志、遥测或错误报告发送图片或像素；
- 不写入 WordPress Media Library；
- 不写入对象存储；
- 不写入 `localStorage`；
- 不写入 `IndexedDB`；
- 不注册包含客户照片的 Service Worker 缓存；
- 刷新或关闭页面后，应用不能恢复照片和场景；
- 导出在浏览器中完成。

准确的用户说明应为：

> The application processes and exports the selected photo in your browser. It does not upload or persist the photo to GDHE or WordPress servers.

不得承诺浏览器或操作系统绝不会为解码或 Blob 产生任何不可控的临时缓存。

### 11.2 允许服务端保存的数据

以下数据与客户照片无关，可以按最小化原则保存：

- 访问申请人姓名；
- 公司；
- 工作邮箱；
- 国家或地区；
- 可选 WhatsApp；
- 申请用途；
- 申请状态；
- 授权、撤销和过期时间；
- 令牌哈希或 session 版本。

### 11.3 本地资源生命周期

实现必须在更换图片、退出编辑器或销毁组件时：

- `URL.revokeObjectURL()`；
- `ImageBitmap.close()`；
- 释放 OpenCV `Mat`；
- 清理 Worker；
- 清空撤销历史中的像素引用。

## 12. 几何与尺寸校准模型

### 12.1 坐标系统

所有几何点均相对原始图片保存为 `0..1` 的归一化坐标：

```text
normalizedX = originalPixelX / originalImageWidth
normalizedY = originalPixelY / originalImageHeight
```

预览和导出必须使用同一套几何函数。工作图只影响显示分辨率，不改变几何事实。

### 12.2 基础比例

若参考线像素长度为 `referencePixels`，用户输入实际长度为 `referenceMm`：

```text
localPixelsPerMm = referencePixels / referenceMm
```

该比例只对参考线附近、相同平面和相近方向可靠。

### 12.3 单向校准

默认模式：

- 用户提供一段横向或轨道方向的真实距离；
- 系统建立局部显示比例；
- 适合正面拍摄和销售展示。

不得用一个横向参考线声称精确恢复所有竖向和深度尺寸。

### 12.4 双向校准

高级模式可允许：

- 横向参考线；
- 纵向参考线。

双向比例可改善电机高度等视觉映射，但仍不能恢复真实相机内参或跨平面深度。

是否纳入第一版完整编辑器，由几何 PoC 的易用性结果决定；单向校准是最小必需能力。

### 12.5 四点透视

静态窗帘模板从标准矩形映射到 `curtainQuad`。候选实现：

- OpenCV.js `getPerspectiveTransform` + `warpPerspective`；
- 在 PoC 证明 OpenCV.js 体积或性能不可接受时，再评估轻量 WebGL 四边形映射。

首个 PoC 默认验证 OpenCV.js，不提前建设多实现抽象层。

### 12.6 无效几何

以下情况必须阻止继续或提示重新调整：

- 四点交叉；
- 四边形面积过小；
- 任意三点近似共线；
- 轨道线长度过短；
- 参考点重合；
- 输入尺寸为零、负数或明显异常；
- 窗帘底部高于顶部；
- 透视角度超过首版支持范围；
- 元素完全离开图片。

### 12.7 视觉近似边界

即使完成校准，以下部分仍使用标准视角资产：

- 电机深度；
- 墙码伸出距离；
- 双轨前后间距；
- 天花板和墙面夹角；
- 产品遮挡和接触阴影。

正式输出不能被描述为施工依据。

## 13. 静态窗帘模板系统

### 13.1 产品边界

- Wave 2.2×：窄、标准、宽；

原因：

- 避免跨域图片使 Canvas 失去导出能力；
- 便于版本控制；
- 便于审查 assetKey；
- 便于视觉回归；

WordPress 只保存 `assetKey` 和业务映射，不直接作为任意可导出素材的来源。

### 14.6 资产缺失策略

缺少以下任一条件时，该组合必须不可选：

- 产品尺寸；
- 正确视角；
- 锚点；
- 兼容规则；
- 对应安装资产；
- 已批准状态。

不得自动使用其他型号素材代替。

## 15. 访问申请与开放模式

### 15.1 访问模式

唯一服务端配置入口：

```text
approval_required
public
disabled
```

编辑器不包含额度、套餐或项目权限。

### 15.2 审批访问的最小流程

推荐首版流程：

```text
用户提交申请
  → WordPress 保存最小申请元数据
  → 管理员批准/拒绝
  → 批准后生成一次性或短期访问链接
  → Next.js Route Handler 验证
  → 写入 HttpOnly session cookie
  → Server Component 再次验证
  → 进入编辑器
```

不建设：

- 用户密码；
- 忘记密码；
- 个人中心；
- 子账号；
- 团队；
- 额度；
- 项目列表。

### 15.3 权限检查边界

如果接入时仍使用 Next.js 16：

- `proxy.ts` 只做乐观入口检查和快速跳转；
- Server Component/DAL 执行真实授权；
- 每个敏感 Route Handler 独立验证；
- 不能只依靠 Proxy。

版本和具体 API 必须在实施任务中重新核对。

### 15.4 撤销

如果要求后台撤销立即生效，不能只使用长期无状态 Cookie。首版需要在以下方案中选择最小可行者：

1. 短 TTL + 服务端授权状态核验；
2. session 记录；
3. 用户授权版本号/revocation 记录。

最终选择由权限 PoC 冻结。

### 15.5 未来公开

切换到 `public` 后：

- 页面不要求申请记录；
- 编辑器逻辑不变；
- 客户照片本地处理逻辑不变；
- 仍保留 GDHE 品牌和免责声明；
- 不自动启用项目保存、分享或额度。

## 25. 测试与验收矩阵

### 25.1 照片边界

- 选择照片后网络面板无图片上传；
- 导出时网络面板无图片上传；
- 日志和错误监控无 Blob/Base64/像素；
- `localStorage`、`IndexedDB` 无照片或 SceneState；
- 刷新后无法恢复；
- 更换照片后旧资源释放。

### 25.2 几何

- 归一化坐标在工作图和原图一致；
- 四点不可交叉；
- 保存于内存的点位在缩放后不漂移；
- 轨道厚度依据产品尺寸和校准关系；
- 电机纵横比锁定；
- 电机锚定轨道端点；
- 窗帘模板稳定映射；
- 预览和导出一致。

### 25.3 业务规则

- 窗帘盒电动的场景图可隐藏电机；
- 嵌入式电动必须显示电机；
- 手动系统不能选择电机；
- 顶装和墙装只显示对应安装件；
- 缺少资产的组合不可选；
- 未验证产品不可发布；
- 窗帘模板不输出 BOM 或用布量。

### 25.4 访问

- `approval_required` 未授权不能进入；
- 已批准可以进入；
- 撤销按已冻结语义生效；
- `public` 不依赖批准记录；
- `disabled` 不加载编辑器；
- Proxy 不能作为唯一授权证据。

### 25.5 品牌与输出

- Logo、网址、免责声明不可移除；
- 无经销商 Logo；
- 无白标；
- 输出不包含客户姓名等未输入的身份信息；
- Canvas 保持可导出；
- PNG/JPEG 下载通过；
- WebP 仅能力检测后出现。

### 25.6 产品真实性

- 每个型号有权威来源；
- 每个尺寸有来源和确认时间；
- 每个 assetKey 指向正确产品；
- 每个电机有正确侧向/安装视角；
- 每项兼容关系有业务确认；
- 示例数据不会进入生产目录。
